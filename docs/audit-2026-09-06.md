# Auditoria e correcoes - 2026-09-06

Escopo: codebase completo da extensao Firefox, com revisoes independentes de
captura, persistencia/interface e ciclo de vida. Auditoria Full: envolve APIs do
navegador, concorrencia e risco de perda de gravacoes. Stack: TypeScript, DOM,
WebExtensions MV3, IndexedDB, MediaRecorder, Bun/Vitest/Vite.

## Problemas confirmados e corrigidos

| Prioridade | Problema anterior                                                                                  | Correcao e evidencia                                                                                                                        |
| ---------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Alta       | Popup mantinha "Saving..." depois de salvar                                                        | Escuta mudancas de estado da sessao; repro DOM falhava antes e agora retorna Ready com botao habilitado.                                    |
| Critica    | Stop apos fim natural da midia nao entregava o blob                                                | Hooks preservam chunks e timestamp final, sem parar novamente um recorder inativo. Repro dos dois hooks e captura real no Firefox passaram. |
| Alta       | Armamento imediato podia abortar o proprio vencedor; dois frames podiam ganhar                     | Estado armado estabelecido antes do envio e vencedor escolhido antes do primeiro await. Erro de frame perdedor nao encerra o vencedor.      |
| Alta       | Eventos podiam ler estado antes da hidratacao; limite de duracao sumia na suspensao                | Router aguarda boot; prazos persistidos e alarms acordam o background. Repro preservou o deadline original.                                 |
| Alta       | Navegacao do iframe ativo deixava estado de gravacao obsoleto                                      | Limpeza do frame ativo; navegacao de outro frame preserva a captura e remove somente sua URL.                                               |
| Critica    | Requests IndexedDB concluidos eram tratados como save mesmo se a transacao abortasse depois        | Save/delete aguardam commit; abort rejeita. Falha de persistencia chega ao popup. Repro aborta a transacao apos success do request.         |
| Alta       | Erros em export/delete/play deixavam UI travada; resposta antiga podia substituir filtros recentes | Rejeicoes recuperam controles; cargas obsoletas sao descartadas e players destruidos nao voltam a tocar.                                    |
| Media      | Download concluido antes da resposta da API vazava object URL                                      | Listener registrado antes do download e reconciliacao dos eventos antecipados.                                                              |
| Media      | Reset das configuracoes podia ser sobrescrito por save em andamento                                | Fila de escritas e cancelamento do debounce; falhas visiveis.                                                                               |
| Media      | Controles nativos/autoplay nao passavam pelo wrapper play()                                        | Observacao adicional do evento play no documento.                                                                                           |
| Media      | Infraestrutura Firefox importava geckodriver.path inexistente                                      | Usa download() do pacote instalado; suite Firefox voltou a executar.                                                                        |

Callers revisados: popup/hotkey/router -> Orchestrator -> tres recorders;
RECORDING_COMPLETE -> saveRecording -> saveCapture -> Repository; app ->
recordingCard/AudioPlayer; configuracoes -> saveSettings/resetSettings. Foram
inspecionados tambem encoder, templates e NetworkRecorder sem mudancas especulativas.

Revisao final de concorrencia: um save/export antigo que terminava depois de
navegar e iniciar outra gravacao limpava o estado novo. Um token local agora
limita a limpeza e o erro a sessao que iniciou aquele save. Repros de sucesso
e falha antigos preservaram `recording` na sessao nova.

## Validacao executada

- `bun run test`: 79/79 testes, 9 arquivos.
- `bun run test:e2e`: 12/12 testes reais no Firefox, 66,06 segundos. Inclui audio,
  video com audio, Web Audio, detached audio, Shadow DOM, iframes, MSE, armamento
  e recusa do fixture DRM.
- `bun run scripts/debug/audit-popup.ts`: conclusao do save, recuperacao de
  mensagem rejeitada e remocao de listener.
- `bun run scripts/debug/audit-storage-ui.ts`: 10 cenarios corrigidos; `--before`
  consulta o baseline `79214b0` para demonstrar os problemas anteriores.
- Harness temporario de captura: 10 cenarios de hooks e limpeza de ambos drivers
  apos timeout. Usa doubles; nao substitui Firefox real.
- `bun run scripts/debug/audit-firefox.ts`, apos build de producao: audio termina,
  Stop salva uma gravacao de 9.847 bytes, estado volta a idle e decodeAudioData
  confirma 27.528 frames mono. Os tamanhos variam com o tempo de execucao.
- `bunx tsc --noEmit`, `bun run lint`, `bun run build`: passaram.
- `bun run lint:ext`: zero erros, avisos e notices.

Os scripts em scripts/debug sao verificacoes ad hoc reutilizaveis, fora da suite
formal. O script Firefox inicia um servidor temporario e usa perfil isolado;
encerra o navegador e servidor ao terminar. Os testes nao alteram gravacoes do
perfil Firefox pessoal.

## Limites

- Audio ainda fica em memoria no contexto de captura ate a conclusao. Navegar,
  fechar a aba ou um crash pode perder audio ainda nao salvo; nao ha backup
  incremental nesta alteracao.
- MAIN-world hooks compartilham o contexto da pagina. Tags postMessage sao
  roteamento, nao autenticacao contra scripts da propria pagina.
- A suite usa fixtures locais, incluindo DRM simulado. Nao comprova cobertura de
  todos os sites, DRM real, streams proprietarios ou gravacoes de varias horas.
- Alarmes recuperam prazos, mas nao garantem disparo com precisao absoluta.
- Auto-export pode falhar depois do save; o original fica no gerenciador e a
  falha e registrada no log. "Download started" nao significa download concluido.
- A tentativa inicial via file:// nao encontrou o content script. A validacao
  real passou com as paginas HTTP locais autorizadas pelo usuario.
